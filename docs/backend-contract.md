# 后端接口约定草案

以下为待实现接口，不是已部署服务。客户端当前所有生产方法均明确失败。

## 基本原则

- 服务器从受信任登录流程获取内部身份，不采纳请求体中的任意作者 ID。
- 位置数据包含坐标系、时间和精度。地图展示与距离计算必须明确坐标系并统一转换。
- 设备位置与相机信息均来自客户端，只能作为分层到场判断的证据，不能保证绝对真实。
- 写入时及分层读取时重新校验位置新鲜度、精度和作用范围；不能永久复用一次解锁凭证。
- 公开与私聊身份不使用可跨场景公开关联的 ID。
- 内容、图片和评论按读取层次分开返回，生产客户端不得包含演示全文数据。
- 图片使用受控存储，签名读取权限与地点读取权限一致。普通公开下载地址不适合隐藏原图。
- 所有真实发布在完成内容治理与权限方案之前保持关闭。

## 接口

| 方法 | 输入要点 | 服务端职责 |
| --- | --- | --- |
| `createPresenceSession` | 新鲜定位、精度、坐标系、服务端挑战应答 | 校验可用证据，发放短时、限定场景和操作的到场凭证 |
| `getNearbySummaries` | 当前定位与浏览范围 | 返回允许看到的点位、数量与公开概要，不返回全文或原图地址 |
| `readThread` | `sceneId`、`threadId`、当前定位／凭证 | 决定 dot／preview／full 层次，只返回对应内容 |
| `createPost` | 到场凭证、文本、受控图片引用、照片标记 | 重新校验到场、所有权、内容与频率；绑定场景 |
| `createComment` | 到场凭证、`threadId`、文本 | 现场验证后写入，不接受离场评论 |
| `setLike` | 到场凭证、`threadId`、目标状态 | 去重、限频，防重复点击和刷票 |
| `requestPrivateChat` | 到场凭证、原留言 ID、幂等请求 ID | 确认现场发起、作者愿意接收、未屏蔽，创建待同意申请 |
| `acceptPrivateChat` | 申请 ID、幂等请求 ID | 校验接收者权限，原子消耗发起者有效权益并建立会话 |
| `sendPrivateMessage` | 会话 ID、消息 ID、内容 | 校验成员和会话状态；已开通会话不再要求到场 |
| `destroyConversation` | 会话 ID、幂等请求 ID | 标记不可恢复的销毁状态，停止收发与读取，触发内容与媒体清除及多端同步 |

还需要本人内容删除、举报、屏蔽、通知拉取、支付回调和权益恢复接口。

## 会话与付费状态

建议使用显式状态：`pending → active → destroyed`，待同意申请另可进入 `declined`／`cancelled`。`destroyed` 为终态，旧消息、重试请求和离线同步不得让会话复活。

同意、扣权益和建会话应具备一次性执行保障。支付订单、权益账本和消息内容分开保存。以服务端验签和查单确定支付结果，不能只信客户端“支付成功”。

## 销毁流程

1. 校验双方之一的权限，将会话写入销毁终态，立即停止服务端读写。
2. 删除活动消息与图片，撤销仍可用的下载访问，触发缓存清理。
3. 向在线设备发送销毁事件；离线设备下次同步时先处理销毁状态，再呈现会话。
4. 将客户端缓存、备份与第三方消息服务纳入删除策略，并核实供应商接口的实际语义。
5. 付款账本和必要记录独立处理，遵循预先明确的留存规则。

无法控制对方截图、录屏、修改客户端或自行导出的副本。没有联网的设备不能保证即时执行远程删除。
